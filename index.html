What is SMTO

The task runtime for the model you run.

A model on its own can only answer. SMTO gives it what real work takes: tools for files, commands, documents and the web; Gateways that run those tools on the computers you choose; permission checks and approvals; and saved progress, so a task can pause, wait and pick up where it left off. It’s built so smaller local models can finish multi-step work, and the same runtime works with larger or hosted models.

How it works

Ask. Let it work. Review.

Tell your AI the outcome you want. It can take the next step using the tools you allow, work with the results, and ask when a decision needs you.

  1. 01

    Describe the job.

    Ask in everyday language and choose the computer it should run on. Plan mode lets you agree on an approach before anything changes.

  2. 02

    Let it take the steps.

    The model chooses each action. SMTO checks access, runs the tool on the selected Gateway and returns the actual result for the next step.

  3. 03

    See what happened.

    Read the answer with the activity behind it. Check important results against their sources or files.

When configured, longer tasks can continue, wait for input, or run on a schedule while the required systems are available.

In practice

See it work.

Screens from SMTO itself. Every task shows its plan, its progress and the evidence behind the answer.

Activity

Every step, on the record.

Open a task’s activity to see each command the model chose, where it ran, its exit status and the output that came back.

  • The command and the folder it ran in
  • The Gateway that ran it
  • Exit status and captured output

Approvals

Nothing changes without you.

When a step needs access it doesn’t have, the task pauses and shows you the exact action. Approve it once, allow it more widely, or stop the task.

  • The exact command before it runs
  • Choose how far a decision applies
  • Deny and stop at any point

Questions

It asks instead of guessing.

When a choice belongs to you, the model asks, offers suggested answers and waits for your reply before it continues.

  • Pick a suggested answer or write your own
  • The task waits; nothing is assumed
  • Work resumes where it paused

Workflows

Make it routine.

Save a request as a workflow, run it whenever you need it or on a schedule, and look back at every run.

  • Reusable requests, one click to run
  • Schedules and reminders
  • Run history for every workflow

More things to ask

Handle repetitive project work

“Create the next version of this project, preserve my unfinished changes, and publish the new branch.”

Check the repository, determine the next version, make the branch, and verify it was published.

Work across computers

“Build this project on my other computer and prepare the finished files for release.”

Use the chosen computer, follow build progress, and inspect the results.

Investigate an application issue

“My editor is behaving strangely. Check its configuration and help me reset the affected files.”

Diagnose the likely cause, explain the changes, and run the approved steps.

Organize files and storage

“Move these large files to another drive, and check that everything copied correctly.”

Inspect source and destination, perform the approved copy, and verify what arrived.

Work where you want

One workspace. All your computers.

Your AI doesn't have to work on the computer in front of you. Install a Gateway on a laptop, workstation or server, then choose the machine that has the files or tools a task needs.

  • Each computer keeps its own files, credentials and permissions
  • See connection status and updates for every Gateway
  • Choosing a computer doesn't share files with the others

Your model

Bring your own model.

SMTO isn't a model provider. Connect a compatible model running on your own hardware or a supported online service, and keep the same workspace, tools and history when you change models.

Local models

Run a model on hardware you control. On Linux, the Inference page can install, start and monitor vLLM and llama.cpp models for you.

Online models

Connect a supported hosted model service when that's the right fit.

The name reflects SMTO's roots in smaller models, not a limit on model size. The model you choose still shapes the quality of its reasoning and answers.

Stay in control

Know what your AI is doing.

Useful AI needs access to real tools. SMTO helps keep that access understandable: see the work, follow results, and decide whether to approve actions that require your permission.

  • See the activityReview tool actions, results, and errors.

FIND YOUR FIT

Different tools. Different strengths.

SMTO is built for people who want their own AI model to carry out real work—with privacy choices, focused context, permissions, and progress they can inspect. Developer frameworks, coding agents, and visual automation platforms approach different parts of that problem.

These products are not all direct substitutes. See where each excels, and where SMTO—or another approach—may be a better fit for your task.

Where SMTO may not be the best fit

We think people should know the trade-offs before choosing an AI work environment.

SMTO considerations and trade-offs.
ConsiderationWhat it means for SMTO
The model still mattersSMTO can structure work and provide tools, but it cannot replace a model's reasoning ability or guarantee correct outcomes. It can help a model keep track of a task, but the model may still misunderstand a request or interpret a result incorrectly. Check important answers against the underlying files or results.
No proven parity with leading coding agentsWe have not published a controlled head-to-head benchmark showing SMTO matches Codex or Claude Code on coding tasks. Feature descriptions are not measurements of coding quality, speed, or reliability. Evaluate the kinds of tasks you actually plan to run with the model and tools you will use.
You manage your setupConnecting models, tools, and computers takes configuration and upkeep. A fully managed service may be simpler. You choose a compatible model endpoint, make the required tools available, and keep execution computers connected. Saved tasks and schedules still depend on those services being available.
Smaller ecosystemSMTO does not yet have the breadth of public integrations, tutorials, or community support of established platforms. A workflow may need manual configuration or an integration you build yourself. Check that the tools and guidance you need are available before committing to a larger rollout.
Not designed as an autocomplete-first editorIf inline coding suggestions are your main priority, a dedicated IDE assistant may suit you better. SMTO is organized around asking for work, following tool activity, and reviewing results. It is not built around predicting the next few characters as you type code.
Privacy depends on connectionsLocal models can keep model inference on your hardware, but online model providers and connected services may receive task data. For example, a web or account integration can contact an external service even when the AI model is local. Review both the model endpoint and each tool's data access.
Guardrails reduce risk; they do not remove itPermission checks and activity history help you stay informed, but sensitive actions and results still need appropriate review. Before approving a sensitive operation, check the action and target computer. Afterwards, inspect the actual result; authorization is not proof that an action was correct or successful.

SMTO is intended to make practical task execution accessible with the model and computers you choose. The right choice depends on the work you need done.

Get started

Install SMTO in minutes.

Download the self-contained build for your platform, start the Gateway and the Server, then connect a model in your browser. There is no Python or package setup to do first.

Choose your platform

  1. Download the Gateway, the Server and the checksums

    mkdir -p ~/smto && cd ~/smto
base=https://github.com/vinithbraj/smto/releases/latest/download
curl -L -O "$base/smto-gateway" -O "$base/smto-server-inference" -O "$base/SHA256SUMS-linux"

  2. Check the downloads against the published checksums

    sha256sum -c --ignore-missing SHA256SUMS-linux

  3. Start the Gateway in one terminal

    chmod +x smto-gateway smto-server-inference
./smto-gateway --host 127.0.0.1 --port 8787

  4. Start the Server in another, then open http://127.0.0.1:8011

    ./smto-server-inference --host 127.0.0.1 --port 8011 --manual-port 8013

Use smto-server-external instead when your model runs on another machine or service. The binaries need glibc 2.35 or newer (Ubuntu 22.04 and later). The first start takes longer while a private runtime is unpacked.

  1. Download smto-server and smto-gateway .deb packages and SHA256SUMS-linux from the latest release

    Open the latest release ↗

  2. Check the packages against the published checksums

    sha256sum -c --ignore-missing SHA256SUMS-linux

  3. Install both packages

    sudo apt install ./smto-server_*_amd64.deb ./smto-gateway_*_amd64.deb

  4. Open SMTO Server Setup and SMTO Gateway Setup from your applications, or run setup in a terminal

    smto-server --setup-wizard cli
smto-gateway --setup-wizard cli

Packages need an internet connection during setup. Setup runs as your regular account and asks for authorization only for the system steps that need it.

  1. Download the two apps and the checksums

    mkdir -p ~/smto && cd ~/smto
base=https://github.com/vinithbraj/smto/releases/latest/download
curl -L -O "$base/SMTO-server-macos-x86_64.zip" -O "$base/SMTO-gateway-macos-x86_64.zip" -O "$base/SHA256SUMS-macos-x86_64"

  2. Check the downloads, then unzip them

    grep -E 'SMTO-(server|gateway)-macos' SHA256SUMS-macos-x86_64 | shasum -a 256 -c -
unzip -q SMTO-server-macos-x86_64.zip && unzip -q SMTO-gateway-macos-x86_64.zip

  3. Start the Gateway in one terminal

    ./SMTO-gateway.app/Contents/MacOS/gateway --host 127.0.0.1 --port 8787

  4. Start the Server in another, then open http://127.0.0.1:8011

    ./SMTO-server.app/Contents/MacOS/server --host 127.0.0.1 --port 8011 --manual-port 8013

The apps are built for Intel Macs and are not signed or notarized. If macOS blocks them, right-click each app and choose Open once, or follow your organization's software policy.

Then connect a model.

In SMTO, open Settings → Model routing and enter your model's endpoint: for example a llama.cpp or vLLM server such as http://127.0.0.1:8080/v1, or an online provider with its API key. On Linux, the Inference page can install and start a local model for you.

Requirements

  • Linux x86_64 with glibc 2.35 or newer, or macOS on Intel
  • About 150 MB per component; Python is bundled
  • A model: local with llama.cpp or vLLM, or an online provider

Current builds are development releases. They are not signed, and the macOS apps are not notarized. A matching SHA-256 checksum shows that a file arrived intact; it does not show who published it.
