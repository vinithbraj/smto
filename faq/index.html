Understanding SMTO

What is SMTO, and what does its name mean?

SMTO stands for Small Model Task Orchestration. It gives a compatible AI model a workspace, tools, and a way to carry out tasks on computers you choose. You describe a result; the model proposes actions, while SMTO manages their execution, access checks, and activity records. You supply the model connection and review the outcome. See how it works.

Link to this answer ↗

How is SMTO different from a chatbot or an AI model?

SMTO is the software around the model. The model interprets your request and chooses steps; SMTO connects those decisions to available tools and records what happened. A chat response may describe a command without running it. An authorized SMTO task can execute tools and produce files or other real changes. A confident answer still needs checking against those results. Explore the task loop.

Who is SMTO for?

SMTO is useful for people who want their chosen AI to work with files, tools, and computers they control, and who are willing to configure access and verify results. Personal projects, experimentation, and learning are examples. Work for an employer, clients, or an organization falls under separate licensing requirements. Start with a small task whose result you can inspect. See examples and the License.

What can I ask it to do, and what makes a good first task?

Available tools can help inspect files, investigate a problem, research information, or create an output you can review. For a first task, use a copy of a non-sensitive text file and ask for a summary with references to the original passages. Select the correct computer and limit access to what the task needs. Compare the answer with the source before trying changes to important data. Browse task examples.

Do I need programming experience?

You can describe tasks in ordinary language; you do not have to write a program for every request. Setup and troubleshooting can still require technical experience, especially when installing from source, configuring a model endpoint, or connecting another computer. You should understand the access you grant and how to check the requested result. Ready-made downloads have their own instructions. Read the setup guide (text).

Getting started

What do I need before installing?

You need a suitable computer, permission to install and run the software, and access to a compatible AI model. The Server coordinates tasks; a Gateway runs machine-local tools. Prepare backups and read the bundled License and EULA before accepting them. Source installation requires Python 3.11 or newer and the project files; ready-made packages have separate instructions. Additional tools may have their own requirements. Read the setup guide (text).

Link to this answer ↗

Which operating systems support the Server and Gateway?

The source setup guide covers the Server on Linux and macOS, and Gateways on Linux, macOS, and Windows. Windows Gateway instructions are specifically for running tools on that computer. For ready-made packages, check the operating system, processor architecture, and Server or Gateway component offered by the exact release. Optional tools can have narrower compatibility than the core installation. Check downloads and the source setup guide (text).

Link to this answer ↗

Do I need a GPU or a powerful computer?

Hardware needs depend on where the model runs and which tools you use. A model on another machine or an online service does not require its inference hardware on your SMTO computer. A local model needs enough memory and compute for that model and its settings. Browsers and other tools add their own demands. Check those requirements and try a small task before committing to a larger workload. Learn about model choice.

Link to this answer ↗

Does the download include an AI model?

SMTO does not bundle model weights or launch a model during installation. Its inference-enabled Linux controller provides an Inference area to register or build a runtime, select or download a model, and launch it. Both controller variants support external model endpoints; the external-only variant omits inference management. Model files, credentials, hardware, and provider terms remain your responsibility. Read inference setup (text).

Link to this answer ↗

Can I use SMTO from my phone or another browser?

SMTO has desktop and mobile browser interfaces for accessing your running Server. Your browser needs a reachable, appropriately secured connection and the required sign-in. Opening the interface on a phone does not install a Gateway there or give the agent access to that phone's files and apps. Tools still run on their configured computers or services. Understand execution targets.

Choosing your AI

Which model providers and local model servers work with SMTO?

Use a model endpoint supported by your SMTO version, with the tool-use behavior your tasks require. The current configuration guidance covers compatible OpenAI-style endpoints and local services including vLLM, llama.cpp, Ollama, and LM Studio, with different capabilities for each. An endpoint being reachable does not prove that every model or setting works well. Verify a small task with your chosen configuration. Read model configuration (text).

Link to this answer ↗

Is SMTO only for small models?

No. Smaller models influenced SMTO's design, but larger compatible models can use the same tools and task structure. Focused tool choices and saved observations can help organize work when context is limited. They cannot supply knowledge or reasoning the model lacks, and they do not guarantee that a smaller model will match a stronger one. Choose by testing representative tasks and reviewing the results. Explore the model approach.

Link to this answer ↗

How do I connect or switch my model?

Configure the endpoint and relevant settings in Mission Control → Model Configuration, then select the model using the Chat model selector. Check the address, credentials where required, and whether the service is running. Some settings depend on provider support. New task settings do not necessarily replace the settings captured by work already underway. Read model configuration (text).

Link to this answer ↗

Can SMTO work without an internet connection?

Yes, for tasks whose model, files, and tools are already available locally or on a reachable private network. Prepare the model files, required software, and Gateway connections first, then test the actual task with internet access disabled. Online model providers, web research, downloads, and remote service integrations still need their networks. A local model alone does not make every tool offline. Read the privacy and permissions guidance.

What model-provider or other third-party costs might apply?

Your model provider and connected services can charge for their own usage, independently of SMTO's license. An automation task may make several model or service calls; the startup model check may also incur provider usage. Local inference uses your hardware and electricity. Review provider terms and billing controls before running unattended work. SMTO's personal-use allowance does not make third-party services free. Read the License.

Computers and tools

What is the difference between the Server and a Gateway?

The Server, also called the controller, coordinates tasks, model requests, and recorded state. A Gateway runs machine-local tools on the selected computer. The model service is another component: it supplies the AI decisions. These components can share a computer or run separately. Some tools run in the controller or contact online services rather than using a Gateway. See how computers connect.

Link to this answer ↗

Can everything run on one computer?

Yes, if that computer supports the needed components and has enough resources. You can run the Server, a local Gateway, and a compatible local model service together. They still have separate configuration and availability requirements. You can also keep the Server and Gateway together while using a model elsewhere. Select the correct Gateway before asking for work on local files. Read the setup guide (text).

Link to this answer ↗

Can one SMTO installation work with several computers?

One controller can connect to several configured Gateways. Choose the target that has the files and software needed for the task. Each host needs its own Gateway setup, suitable permissions, and a reachable connection. Selecting one target does not automatically broadcast work to all computers or provide automatic failover. Remote Gateways also need their own updates. Learn about execution targets.

Link to this answer ↗

Are files automatically shared between connected computers?

No. Connecting a Gateway does not synchronize files or merge computers into one filesystem. Paths, installed programs, accounts, and permissions belong to their respective hosts. A file on your laptop is not automatically present on a remote server. Check the selected target and path before reading or changing data, and arrange any needed transfer through an appropriate authorized operation. Review the computer boundaries.

Link to this answer ↗

Which tools and integrations are available, and what must I configure?

SMTO groups tools into Skills for work such as files, commands, browser tasks, and supported services. Availability depends on your version, installed software, selected capabilities, permissions, and connected accounts. Installation may prepare dependencies, but it does not provide every service, credential, model, or operating-system permission. Check the available capabilities in your installation and review any access request. Read about tools and permissions (text).

Privacy, permissions, and safety

What information stays on my computer, and what may leave it?

The controller runs in the environment you choose, but data flow depends on the model and tools. An online model provider receives information included in requests, potentially including instructions, tool results, and retrieved Memory. Tools may contact separate services even with a local model. The public website does not run your tasks or read your conversations. Review the whole task path when handling private data. Read privacy and permissions.

Link to this answer ↗

Which files and accounts can SMTO access?

Access depends on the selected tools, task permissions, Gateway account, and connected services. A tool being installed or visible is not the same as permission to use it. Operating-system and service permissions also matter. Use accounts and folders with access limited to the task, and check which computer an operation targets before authorizing it. Read the access guidance (text).

Link to this answer ↗

Does every action require my approval?

No. Some actions can proceed under permissions already granted to the task; others require an additional decision. The behavior depends on the action and configured policy. Review the requested operation and target when an approval appears. Approval authorizes the action but does not prove it will succeed or that its result is correct. Do not assume every change will have a separate confirmation. Read about approvals (text).

Link to this answer ↗

Can a model mistake change or delete data, and what precautions should I take?

Yes. SMTO can perform real actions based on responses from the model you configure. Incorrect reasoning or tool choices can modify or destroy data or system state, expose information, or incur charges. Keep appropriate backups, limit permissions, test on copies, and review important results. Unattended tasks need particular care. The EULA describes user responsibilities and the applicable warranty and liability disclaimers. Read the complete EULA.

Link to this answer ↗

Can I stop a task or undo its actions?

Use Stop to request cancellation of the task and its owned work. Cancellation can take time, and an external service may already have acted. Stopping does not undo completed writes, sent requests, or other effects. SMTO does not provide a universal undo for every tool. Inspect the actual result before retrying and use backups or the affected application's recovery tools where available. Read about interrupted work (text).

How should I handle API keys, credentials, and sensitive information?

Use the provided credential and private-parameter settings where applicable. Avoid putting passwords or keys in task descriptions, conversation notes, or long-term Memory. Retrieved information may later be included in model requests. Redaction does not cover every possible output, so review logs, screenshots, and diagnostic reports before sharing them. Give connected accounts only the access needed for your task. Read the credential guidance.

Tasks, results, and memory

Will work continue if I close the browser?

An accepted task is managed by the controller rather than by the browser tab. It can continue or wait for input after you close the interface, provided the required services remain available. Closing a tab is different from putting the computer to sleep or stopping the Server, Gateway, or model service. Return to the task's status and activity to check what happened. Read about background work (text).

Link to this answer ↗

Can tasks run later or while I am away?

Supported scheduled and background work can run without keeping the browser open. The controller, model service, relevant Gateway, and any connected services must be available when needed. A sleeping or powered-off computer cannot execute tools, and a task awaiting your approval may remain paused. A saved schedule is not proof that it ran. Check status and results afterward. Read about schedules and waiting (text).

Link to this answer ↗

Why is a task waiting for input, approval, or resources?

Waiting can mean SMTO needs your answer, an access decision, a running operation's result, or available execution capacity. Read the displayed reason and recent activity before retrying. Model and controller concurrency limits can queue work even when the system is healthy. A disconnected Gateway is a different problem from denied permission. Resolve the stated condition instead of repeatedly submitting the same action. Read the activity guidance (text).

Link to this answer ↗

What happens after a disconnection or restart?

Use the saved task status and activity records to understand what was confirmed and what remains uncertain. Where supported, SMTO investigates interrupted work before another action. An operation may have changed a file even if its reply was lost, so repeating it can cause another change. Recovery is not guaranteed for every failure, and execution is not guaranteed exactly once. Verify the underlying result before retrying a write. Read the interruption guidance (text).

Link to this answer ↗

How do I verify that a task actually succeeded?

Compare the requested outcome with the actual file, output, or service state. Review tool activity for errors, unfinished work, and the target computer. A successful tool call shows that an operation reported success; it does not prove the model understood your intent. Completion checks and Task Contracts can help organize verification, but important results still need review. Read how to check completion (text).

Link to this answer ↗

What does SMTO remember between tasks and conversations?

Task records, conversation notes, and long-term Memory serve different purposes. Notes support work within a conversation; Memory can retain selected useful information for later conversations. Saved information is not necessarily included in every model request, and retrieval does not make old facts current. Avoid storing secrets. Retrieved Memory can become part of a request to your configured model provider. Read about context and Memory (text).

Licensing and permitted use

Is SMTO free for personal use?

Free for personal, noncommercial use only. Commercial and organizational use requires a separate license.

The personal-use allowance covers an individual's private hobbies, experimentation, and personal learning under the supplied terms. It does not cover employer, client, or organizational work, even on a personally owned computer. Model providers and connected services may charge separately. Read the permitted-use terms.

Free for personal, noncommercial use only. Commercial and organizational use requires a separate license.

Common problems and help

What should I check if installation or a model/Gateway connection fails?

Start with the actual error and the instructions for your component and platform. Check that the relevant service is running, its configured address and credentials are correct, and the required network path is available. For installation errors, inspect installer output and prerequisites. Do not solve a connection problem by broadly disabling access controls. Distinguish a failed model request from an offline Gateway. Read the setup guide (text).

Link to this answer ↗

Why is a tool missing or unavailable?

A tool may be absent, not selected for the task, blocked by permissions, or dependent on an unavailable program or account. Some optional features are unsupported on particular hosts even when core installation succeeds. Check readiness on the computer that actually runs the tool; updating the Server does not update a remote Gateway. Do not grant unrelated permissions just to dismiss an error. Read about capabilities (text).

Link to this answer ↗

Why is a task slow or producing poor results?

Possible causes include model capability, limited hardware, network delays, unavailable tools, a large task, or waiting for capacity. Check activity to distinguish a queue from active generation or a tool error. Try a smaller, clearly defined task with an inspectable result. A larger timeout cannot fix incorrect reasoning or a crashed service. Review the model settings and verify the output before relying on it. Read model configuration (text).

Link to this answer ↗

How should I prepare for updates and protect saved work?

Read the instructions for the version and installation method you use, and back up important data and configuration before changing the installation. Review active work and use the documented shutdown procedure so state can be saved. Each remote Gateway needs its own update. Keep backups outside locations an automation task can modify, and check that you can restore them. Avoid reset operations unless you intend their documented effects. Read setup and lifecycle guidance (text).

Link to this answer ↗

Where can I find help, report a problem, or request a feature?

Start with the project repository and the instructions supplied with your download for current help and reporting options. Include your version, operating system, component, the steps that led to the problem, and a sanitized error message. Remove secrets and personal data from anything you share; do not post sensitive security details publicly.
